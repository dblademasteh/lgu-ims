# UI/UX Findings — LGU IMS Frontend

## Scope
- 17 pages, 5 shared components, 1 layout, 1 design system (index.css)
- Stack: React 19 + Vite, Tailwind v4 CSS-first, Lucide React icons

---

## Critical (fix before ship)

### 1. LoginPage is fully disconnected from the design system
- **File:** `frontend/src/pages/LoginPage.jsx:365-404`
- **What:** Entire form section uses a `<style>` block defining custom `.form-input` and `.btn-primary` classes with hardcoded colors (`#1B2A4A`, `#B8860B`, `#5A6A7A`), border-radius `2px` instead of the system's `8px`, and `height: 42px` instead of `48px`. Background is hardcoded `#F8F7F4` instead of `var(--surface2)`. No Lexend font, no CSS variables.
- **Impact:** Login is the first screen users see — it feels like a completely different app.
- **Fix:** Delete the `<style>` block; replace with the design system's `.input` and `.btn` / `.btn-primary` classes. Update background to use `var(--surface2)`. Align border-radius to `8px`.

### 2. Clickable table rows are keyboard-inaccessible
- **Files:** `ItemsPage.jsx:214`, `RISPage.jsx` (likely similar), `PurchaseOrdersPage.jsx`, `SuppliersPage.jsx`, `UsersPage.jsx`, `ReceivingPage.jsx`, `PhysicalCountPage.jsx`, `AuditLogPage.jsx`
- **What:** `<tr onClick={...}>` makes entire rows clickable but `<tr>` is not an interactive element. Keyboard users can't activate; screen readers announce nothing.
- **Fix:** Either (a) wrap the primary action in a semantic `<button>` inside the last `<td>`, or (b) add `role="button"`, `tabIndex={0}`, `onKeyDown` handler (Enter/Space), and `aria-label` describing the action to every clickable row.

### 3. Toast dismiss button has no accessible label
- **File:** `components/Toast.jsx:36`
- **What:** `✕` character button with no `aria-label`. Screen reader users won't know what this button does.
- **Fix:** Add `aria-label="Dismiss notification"` to the button.

### 4. Sidebar dropdown relies entirely on mouse hover
- **File:** `components/Layout.jsx:213-248`
- **What:** All dropdown menu items use `onMouseEnter`/`onMouseLeave` for background highlight. No `:focus-visible` style. Keyboard-only users see no feedback when tabbing to dropdown items.
- **Fix:** Add `&:focus-visible { background: var(--surface2); }` to dropdown item buttons. Consider `onFocus`/`onBlur` for React.

### 5. Duplicate `gridTemplateColumns` bug in DashboardPage
- **File:** `frontend/src/pages/DashboardPage.jsx:189`
- **What:** `display: 'grid', gridTemplateColumns: '1fr', gridTemplateColumns: '3fr 2fr'` — second assignment always wins, so the responsive single-column fallback is dead code. Charts never stack on mobile.
- **Fix:** Remove the `1fr` declaration or use a proper responsive grid that switches between `1fr` (mobile) and `3fr 2fr` (desktop) via a media query or CSS class.

### 6. Modal dialogs missing accessible names
- **Files:** `Layout.jsx:269-281`, `LoginPage.jsx:323-363`, `ItemsPage.jsx` (detail/edit modals)
- **What:** `<dialog>` elements lack `aria-label` or `aria-labelledby`. Screen readers announce "dialog" without context.
- **Fix:** Add `aria-label="Confirm sign out"` / `aria-label="Reset password"` etc. to every `<dialog>` element.

## High

### 7. No `aria-selected` on tab buttons
- **Files:** `PurchaseOrdersPage.jsx:26-27`, `ProfilePage.jsx:23` (and likely others)
- **What:** `role="tablist"` contains buttons but no `aria-selected="true/false"` to indicate active tab.
- **Fix:** Add `aria-selected={tab === 'list'}` to each tab button.

### 8. Tables lack `<caption>` or accessible names
- **Files:** Most list pages (Items, RIS, PO, Suppliers, Users, Receiving, Physical Counts, Audit)
- **What:** Screen readers have no way to announce what table the user is in. No `<caption>` and no `aria-label` on `<table>`.
- **Fix:** Add `<caption>` with visually-hidden CSS or `aria-label="Items table"` to each data table.

### 9. Interactive filter controls use inline `<label>` wrapper
- **Files:** `ItemsPage.jsx:184`, `ReceivingPage.jsx:160`
- **What:** `<label>` wrapping a checkbox + text without a proper `htmlFor`. The checkbox is nested, so `htmlFor` can't point to it.
- **Fix:** Change to `<div role="checkbox" aria-checked={...} tabIndex={0}>` with keyboard handler, or restructure so the `<label>` wraps only the text and `htmlFor` points to the checkbox input.

### 10. LoginPage `form-input` height bypasses design system
- **File:** `frontend/src/pages/LoginPage.jsx:366-379`
- **What:** `height: 42px` instead of `48px` (the 3rem design system input height). Hardcoded `border: 1px` instead of `1.5px`.
- **Fix:** After merging with design system classes, ensure inputs are `3rem` (48px) minimum for senior accessibility.

## Medium

### 11. LedgerPage uses Tailwind arbitrary-value badge classes
- **File:** `frontend/src/pages/LedgerPage.jsx:7-12`
- **What:** `bg-neutral/10 text-neutral` etc. use Tailwind arbitrary modifiers that bypass the design token system. The design system already has `.badge`, `.badge-success`, etc.
- **Fix:** Replace with the `.badge .badge-ghost` / `.badge-success` pattern used elsewhere.

### 12. Inline styles everywhere — design system under-utilized
- **Files:** `Layout.jsx:94,97,139,202`, `DashboardPage.jsx` (throughout), `ProfilePage.jsx`, `RISPage.jsx`, `PurchaseOrdersPage.jsx`
- **What:** Hundreds of inline `style={{ background: 'var(--surface)' }}` and `style={{ color: '...' }}` throughout components. These bypass CSS cascade, can't be overridden by the design system, and make changes laborious.
- **Fix:** (a) Add missing utility classes to index.css as needed, (b) refactor pages to use CSS classes over inline styles, (c) extract repeated inline patterns into shared components.

### 13. `color-mix` with `transparent` produces `oklab` warnings in some browsers
- **Files:** Throughout (e.g., `index.css:109`, `Layout.jsx:139`)
- **What:** `color-mix(in oklab, var(--ink) 10%, transparent)` is the pattern used everywhere. This is valid but heavy. The `--line` variable uses this pattern at `10%` — very low contrast.
- **Fix:** Ensure border colors are at least 2:1 contrast ratio. The current `--line` at `10%` may produce ~1.2:1 which is nearly invisible. Consider raising to `15-20%` for borders.

### 14. Chart tooltips hardcoded to 12px
- **File:** `DashboardPage.jsx:16`
- **What:** `CHART_TOOLTIP` has `fontSize: '12px'`. The design system base is 17px. This is below senior-friendly thresholds.
- **Fix:** Increase to `13px` minimum in tooltip style object.

### 15. Budget card height hardcoded to 5px
- **File:** `DashboardPage.jsx:95`
- **What:** Progress bar `height: '5px'` — below touch target and visibility standards.
- **Fix:** Raise to at least `8px` (matching `.progress` class).

### 16. Empty state icons use raw SVG instead of Lucide
- **File:** `components/ui.jsx:28-31`
- **What:** `EmptyState` uses a hand-coded SVG box icon. All other icons in the app use Lucide React.
- **Fix:** Import `Package` or `Inbox` from Lucide and use it instead.

## Low / Polish

### 17. Not-found page (App.jsx:22-29) uses `className` instead of CSS classes
- **What:** `className="flex flex-col..."` — Tailwind arbitrary classes. Mixes with `.btn btn-primary` (CSS class). Should be consistent.
- **Fix:** Convert to design system CSS classes.

### 18. No `loading` state on form submission buttons (most pages)
- **Files:** Most forms — RIS create, PO create, Supplier save, etc.
- **What:** Buttons like "Save" and "Submit" don't show a spinner or become disabled immediately on click, creating a perception of unresponsiveness.
- **Fix:** Follow the pattern in `LoginPage` — set `disabled` + show spinner on the first render cycle before async call.

### 19. Footer uses `letter-spacing: 0.14em` — inconsistent with the 0.06em elsewhere
- **File:** `Layout.jsx:260`
- **What:** Footer text uses `0.14em` letter-spacing while the design system uses `0.06em` for mono labels.
- **Fix:** Standardize to design system token.

### 20. No `prefers-reduced-motion` check in Recharts animations
- **File:** `DashboardPage.jsx:211-223`
- **What:** Recharts `Area` and `Bar` components animate by default. The design system has a `prefers-reduced-motion` block in index.css but Recharts is not wrapped.
- **Fix:** Pass `isAnimationActive={false}` to Recharts components, or wrap in a hook that reads `prefers-reduced-motion`.
